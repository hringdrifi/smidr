# キーマップ編集

ファームウェア工程の「キーマップ」では、レイヤーごとにキーへアクションを割り当てます。先にファームウェアを選択すると、その対象で表現できるキーだけをパレットへ表示します。

## 対象別パレット

設計モードでは選択したQMK/VIA、Vial、ZMK、RMK、リマップモードでは接続中のVIA、Vial、ZMKプロトコルがパレットの対象です。対象未確定時に全ファームウェアのキーをまとめたパレットは表示しません。

対象で表現できないキーは一覧から除外されます。対象では利用可能でも、実機のケイパビリティ不足や編集対象未選択によって現在割り当てられない項目は無効表示になります。詳細は[アクション / キーコード・ファームウェア対応表](/reference/actions)を参照してください。

## アクションを割り当てる

キーを選択し、下部パレットのANSI、ISO/JIS、レイヤー、メディア、Macro、Tap Dance、ライティング、特殊から割り当てます。複数キーを選択した場合は同じアクションをまとめて設定できます。

右側のキーマップ設定では、タップ、修飾キー同時押し、Momentary、Toggle、To、Layer Tap、Mod Tap、Macro、Tap Dance、Raw actionを編集します。Layer TapとMod Tapのタップ側も、対象ファームウェアで利用できるキーに限られます。

## レイヤー

レイヤーの追加・削除・切り替えは下部トレイで行います。レイヤー削除時は、そのレイヤーを参照するアクションも整合性が保たれるよう更新されます。透過キーは下位レイヤーへ処理を渡し、何もしないキーはそこで入力を止めます。

## Macro、Combo、Tap Dance

ファームウェア工程の左ナビゲーションから各定義パネルを開きます。設計モードの定義は `.smidr` プロジェクトへ保存され、QMK/Vial/ZMKのソース生成に利用されます。RMKではこれらの定義工程を表示しません。

リマップモードの各パネルは実機のDynamic機能を編集します。設計側の定義を自動で流し込むものではありません。ZMK Studioで新しいbehavior定義を追加する場合は、ZMKソースを出力して再ビルドする必要があります。

## 任意 / Any

標準モデルにない対象固有コードはRaw actionとして入力できます。Raw actionのプロトコルは現在の対象に固定され、別ファームウェアへは自動変換されません。通常のキーはできるだけ標準パレットを使用してください。
